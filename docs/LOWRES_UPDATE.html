160~300px 작은 이미지용 head 추가¶

2026-11-19 배포 업데이트. API 1.2.0 / 패키지 모델 ID cf384-l2sp-aug-lowres-default-20261119. 2026-11-18에 학습한 가중치를 그대로 기본 모델에 적용했다. 새 학습이나 임계값 변경은 없다.

사용법¶

서버를 Ctrl+C로 종료하고 다시 실행한 뒤 브라우저를 새로고침한다. /demo는 **L2-SP + 증강 + 160~300px 학습 (기본)**이 자동 선택된다. API의 model을 생략해도 lowres를 사용한다. 기존 head는 model=adapted로 비교할 수 있다.

API:

POST /v1/predict?model=lowres
X-API-Key: <기존 키>

입력은 기존과 같은 multipart의 file 필드다. CLI는 프로젝트 폴더 안에서 실행한다:

.venv/bin/python client.py my_small_photo.jpg --model lowres

Windows:

.\.venv\Scripts\python.exe client.py my_small_photo.jpg --model lowres

학습에서 달라진 것¶

  • CF384 백본은 그대로 동결하고, 선형 head의 385개 파라미터만 다시 학습했다.
  • 기존 원본 + aug0 + aug1을 보존하고, 160~300px로 축소하는 lowres0/lowres1을 추가했다.
  • 각 view는 좌우 반전 50% → 한 변을 160~300px 범위의 정수 균일 분포로 축소 → JPEG 품질 60~95를 50% 확률로 적용 → 실제 API처럼 512/JPEG95 → CF 전처리 순서다.
  • fold당 원본 280장에서 입력 view가 840개 → 1,400개로 늘었다. 독립 사진 1,400장을 확보한 것은 아니다.
  • λ=.01/.1/1/10을 train에서 학습하고, val의 기존 3조건 평균 50% + lowres 2조건 평균 50%로 선택했다. 임계값은 0.5로 고정했다. test를 보며 λ나 임계값을 맞추지 않았다.
  • 4개 fold head를 동일 비율로 평균한 새 가중치를 models/l2sp_aug_lowres_mean.npz에 저장했다. 기존 l2sp_aug_mean.npz와 원본 CF는 교체하지 않았다.
  • 세 분류기는 같은 CF 특징을 사용하므로 이미지당 큰 백본을 추가로 실행하지 않는다. API는 입력 크기로 모델을 자동 선택하지 않는다.

실제 웹 썸네일 추가 평가 (2026-11-19)¶

실사 32장/생성 32장, 실제 긴 변 160~280px의 Wikimedia CDN 파일에서 기존 head 85.94% → 최신 head 90.63%였다. 실사 오탐은 0/32 → 2/32, AI 누락은 9/32 → 4/32였다. 동일 파일에 추가 JPEG85를 적용하면 최신 head는 81.25%로 내려갔다. Google 서버 썸네일은 아니며 소규모 관측이다. 자세한 한계와 측정표는 작업 요약.

이전 합성 축소 측정 결과¶

작은 test 입력은 기존 이미지를 해당 한 변 크기로 축소하고 JPEG85로 저장한 뒤, API의 512/JPEG95 전처리를 적용한 합성 열화다. 실제 웹 썸네일을 새로 수집한 평가는 아니다.

입력 기존 개선 head 축소 추가 head
기존 4계열, 160px 64.06% 77.19%
기존 4계열, 224px 80.63% 85.94%
기존 4계열, 300px 89.38% 91.56%
기존 4계열, 기본 512 94.69% 95.31%
외부 100장 재사용, 160px 50% 67%
외부 100장 재사용, 224px 56% 72%
외부 100장 재사용, 300px 66% 74%
외부 100장 재사용, 기본 512 81% 84%

외부 100장은 학습/선택에는 사용하지 않았지만 과거 평가에서 이미 본 사진이다. 기존 4계열의 실제 사진 40장도 fold 간 반복되므로 대규모 독립 검증이 아니다. 원본 CF의 학습 노출은 미확인이다.

오탐 tradeoff: 기존 4계열 160px 조건에서 실제 사진 오탐은 1.88 → 15.63%로 늘었고 AI 누락은 70 → 30%로 줄었다. ROC-AUC도 .8283 → .8864로 개선됐지만, 정확도 상승만으로 오탐 문제가 해결됐다고 볼 수 없다. 기본 512 조건의 FPR은 두 head 모두 3.75%였다.

160px 외부 조건에서 새 head의 실제 사진 오탐은 4%, AI 누락은 62%다. 정확도가 개선됐어도 작은 이미지의 생성 흔적이 사라지는 문제는 남는다. 점수만으로 진위를 확정하거나 확대가 정보를 복구했다고 해석하지 않는다. 저해상도 후보의 실제 사진 오탐/기본 조건 tradeoff도 전체 표에서 확인해야 한다.

재현과 검증¶

실험은 ai_image_eval/lowres_adaptation/에 별도로 저장했다. extract_features.py, train_evaluate.py, PROTOCOL.md, LowRes_Head_Training.ipynb가 추출/학습/설정/재현을 담고 있다. results/per_family.csv, external_metrics.csv는 전체 지표와 혼동행렬, predictions.csv, external_predictions.csv, image_changes.csv는 이미지별 점수다.

API의 기존 2개 점수 일치 검사는 유지하고, 160px 파일의 새 lowres 점수를 실험 특징 캐시 계산과 대조하는 테스트를 추가했다. 모델 파일의 SHA256도 검사한다. 원본 프로젝트의 실제 HTTP/독립 실행 검증 로그는 공개 사본에 포함하지 않았다. 서버 요청 중 학습/다운로드는 하지 않는다.
