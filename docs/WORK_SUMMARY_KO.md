# CF384 작업 요약 — 2026-11-19

현재 모델은 **동결 CF384(ViT-S/16) + L2-SP + 기존 증강 + 160~300px 축소 증강으로 학습한 선형 head**입니다. API 1.2.0부터 이 `lowres` head가 기본 결과입니다.

## 거쳐 온 작업

1. **원본 조사·평가:** CF384 공개 가중치와 전처리를 확인하고 실제/생성 이미지의 점수를 비교했습니다.
2. **분류기 개선:** 백본을 동결하고 마지막 선형 분류기 385개 파라미터만 학습했습니다. 일반 L2, L2-SP, 증강, WiSE-FT 등의 후보를 비교한 뒤 L2-SP + 증강을 개선 head로 구성했습니다. L2-SP는 원본 head에서 지나치게 멀어지는 학습을 억제합니다.
3. **저해상도 학습 통합:** 기존 원본 + 증강 2개에 160~300px 축소 증강 2개를 더해 함께 학습했습니다. fold당 원본 280장의 입력이 840 → 1,400개 view가 됐으며, 독립 사진이 늘어난 것은 아닙니다. 검증 데이터로 학습 설정을 선택하고 4개 fold head를 동일 가중치 평균했습니다.
4. **오탐/임계값 점검:** 임계값을 높이면 실사 오탐은 줄지만 생성 이미지 누락이 늘어남을 확인했습니다. 높은 임계값을 배포하지 않고 0.5를 유지했습니다.
5. **실제 웹 썸네일 평가:** 모델을 더 복잡하게 만들기 전에 Wikimedia CDN의 새 이미지 64장으로 동결 평가했습니다. 점수를 보기 전에 표본을 고정했고 테스트로 임계값을 최적화하지 않았습니다.
6. **로컬 Python API:** FastAPI, X-API-Key 인증, 이미지 업로드, 브라우저 데모, Python/확장 연동 예제를 만들었습니다. 이미지당 백본 1회로 세 head 점수를 계산하며 서버는 학습하지 않습니다.
7. **이번 배포:** 최신 `lowres` head를 API·Python·JS·데모의 기본값으로 통일했습니다. 새 학습이나 가중치 변경은 없습니다. 원본/이전 head는 비교용으로 남겼습니다.

## 새 웹 썸네일에서 직접 측정한 결과

실사 32장·AI 32장(SD 계열 20/DALL-E 계열 12), 실제 긴 변 160~280px(중앙값 250px), 임계값 0.5입니다. **Google 서버 썸네일은 아닙니다.**

| 모델 | 정확도 | 실사 오탐 | AI 누락 | ROC-AUC |
| --- | ---: | ---: | ---: | ---: |
| 원본 CF384 | 81.25% | 0/32 | 12/32 | 0.9775 |
| 기존 L2-SP+증강 | 85.94% | 0/32 | 9/32 | 0.9639 |
| 최신 L2-SP+증강+축소 학습 | 90.63% | 2/32 | 4/32 | 0.9697 |

기존 head 대비 오류 5개를 고쳤지만 실사 오탐 2개가 새로 생겼습니다. 개선 폭 +4.69%p의 paired bootstrap 95% 구간은 −3.13~+12.50%p로, 확정적인 개선 증거로 보기는 어렵습니다. 원본 AUC가 최신 head보다 높으므로 모든 분리 성능이 개선된 것도 아닙니다.

**같은 작은 썸네일에 JPEG85 압축을 추가**하면 기존 head 67.19%, 최신 head 81.25%였습니다. 최신 head도 압축에 민감합니다. 실제 웹 파일 그대로인 결과와 이 대조군은 구분해야 합니다.

표본/제작자/생성기가 제한되고, 실사 전부 JPEG와 AI의 JPEG 14/PNG 15/WebP 3이라는 형식 차이도 있습니다. 라벨은 Commons 카테고리·설명·카메라 메타데이터에 근거하며 완전한 진위 증명은 아닙니다. 기존 로컬 학습/평가 866장과 보수적 중복 검사에서 일치 0건이었지만 CF384 사전학습 미노출을 보장하지 못합니다. 큰 파일 12장은 HTTP 429로 받지 못해 큰 미리보기 비교는 동일 52장에만 제한했습니다. 작은/중간 썸네일 64장은 모두 평가했습니다.

## 현재 API에 실제 포함된 기술

- 동결 CF384 특징 + 선형 head, L2-SP, 좌우 반전·리사이즈·블러·JPEG 및 추가 160~300px 축소 학습, 4개 fold head의 산술 평균입니다. fold head 평균은 백본 4회 추론이 아닙니다.
- **TTA·LoRA·GAPL·주파수 결합·WiSE-FT는 현재 배포 추론 경로에 포함되지 않습니다.** 과거 검토/실험과 현재 배포 구성을 구분합니다.
- 점수는 보정된 진위 확률이 아닙니다. 기본 모델 변경이 오탐 문제를 해결했다는 뜻은 아닙니다.

## 업데이트하고 사용하기

저장소 폴더 안에서 서버를 Ctrl+C로 종료한 뒤 실행합니다.

```sh
git pull --ff-only
.venv/bin/python run_server.py
```

Windows 서버 실행: `.\.venv\Scripts\python.exe run_server.py`. 브라우저를 새로고침하세요. API 키는 기존 설치의 것을 그대로 사용합니다. 확장이 `model=adapted`를 명시한다면 `model=lowres`로 바꾸거나 query를 생략해야 최신 기본 모델을 사용합니다. 응답의 `selected_model`이 `lowres`, 현재 `api_version`이 `1.4.0`인지 확인하세요. 설치 명령은 [간단 사용법](../QUICK_START_KO.md)에 있습니다.

공개 저장소에는 키·사진·개인 경로·가상환경·평가 원본 데이터를 올리지 않습니다. [전체 지표](evaluation/web_thumbnail_metrics.csv), [JPEG85 대조군](evaluation/jpeg85_control_metrics.csv), [생성기별 지표](evaluation/web_thumbnail_per_family.csv), [불확실성 구간](evaluation/bootstrap_ci.csv)을 첨부했습니다. 논문 보고 성능이 아닌 이번 로컬 직접 측정 결과입니다.


## 2026-11-23: 인터넷 사용처 검색 연결 (API 1.3.0)

CF384 가중치는 그대로 두고 TinEye 역이미지 검색 어댑터를 추가했습니다. 같은 요청에서 AI 판별과 사용처 URL을 별도로 반환하고, 데모·Python·JS 클라이언트에도 검색 옵션을 연결했습니다. 설정되지 않았거나 실패하면 검색 실패 상태를 반환하며 CF384 결과는 유지합니다. 실제 외부 검색은 계정 키/크레딧과 사용 승인 후 별도 검증해야 합니다. 이번 작업에서는 유료 호출·가입·결제하지 않았습니다. 모의 응답 테스트는 실제 검색 성능 평가가 아닙니다. [설정 방법](WEB_USAGE_SEARCH_KO.md).


## 2026-11-23: 무료 검색으로 변경 (API 1.4.0)

사용자 요청으로 TinEye 유료 검색을 제외하고 SerpApi Google Lens Free 요금제 전용으로 교체했습니다. 매 검색 전 무료 요금제/잔여 한도를 확인하고 유료 요금제·한도 초과·확인 불가면 중단합니다. 이미지 업로드와 exact_matches 검색을 연결했으며 유료 fallback은 없습니다. CF384 모델은 변경하지 않았습니다. 실제 계정 키가 아직 없어 모의 테스트/로컬 HTTP까지만 검증하고 검색 품질 측정은 수행하지 않았습니다. [무료 API 설정](WEB_USAGE_SEARCH_KO.md).
